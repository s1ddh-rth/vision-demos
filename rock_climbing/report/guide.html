Guide

How to run

Film a climb, run it through the dashboard, then read the report. Everything runs on your machine; only the SAM and Qwen calls go out to the VLM Run gateway.

01

Quick start

1

Create the environment (once)

From the rock_climbing folder:

conda env create -f environment.yml
2

Add your API key (once)

Get a key from app.vlm.run (it is shown only once when created, so copy it right away). Copy the example env file to the repo root, one level above rock_climbing, then paste the key after VLMRUN_API_KEY=.

cp ../.env.example ../.env

In Windows cmd: copy ..\.env.example ..\.env

3

Start the dashboard

conda activate rock_climbing
python app.py

Then open http://127.0.0.1:8000. Use --port or --host to change where it listens.

02

Filming checklist

  • Keep the phone still. Use a tripod, or prop it on a water bottle. The pipeline assumes one fixed camera: no panning or zooming.
  • Get the whole route in frame, top hold included. On our test clip the top hold sat at the frame edge, so the hands left the frame on the match and the judge could not confirm a controlled top from pose alone.
  • Pick an easy route with clearly coloured holds, so the climber reaches the top and every hold is visible.
  • Trim the clip to the attempt: a few seconds before lift-off to a few seconds after landing. One clip is one attempt.
  • One climber in frame. Pose tracking follows a single person.
  • Film in SDR if you can. iPhone HDR clips come out washed out on Windows (detection still works, the render just looks pale).
03

Using the dashboard

  1. Upload or pick a clip. Drop a .mov, .mp4, .m4v or .avi, or select one already on disk. The list is newest first and the newest clip is selected by default. A clip that appears while the page is open (uploaded, or moved into data/input/uploads or data/input/current) is picked up within about 10 s (or on Refresh), selected automatically and tagged NEW CLIP. The selected clip is outlined and marked SELECTED.
  2. Hold colour chip. The colour of the route being climbed (blue, green, yellow, red, purple, pink, orange, black, white).
  3. Grade. The route grade, e.g. VB or V2. It is shown in the report.
  4. Use VLM credits. The main pipeline (SAM 3.1 hold segmentation) always costs about $0.025 per clip. With the toggle on, the report adds ~$0.006: crash-pad segmentation, Qwen fall verdicts, dyno checks and a coach note. Off runs the report with --no-vlm (floor used as the landing zone, no verdicts or coach note).
  5. RUN. The button spells out exactly what will run, e.g. Run IMG_0510.MOV · black · VB; check it before clicking. If that clip + colour already has a run, a yellow warning appears under the button instead of starting: Run again anyway or Open existing report. Progress steps then show live under a title naming the clip and colour: Segmenting holds + pose (main.py), then Judge, safety, dyno (safety_report.py). The first log line prints the resolved clip path and colour.
  6. Open report when the run turns DONE.
The runs gallery keeps one card per clip + colour. Each card shows the hold colour as a chip. Re-run analysis redoes only the judge, safety and dyno step (safety_report.py) on a finished run, without re-segmenting the video. Delete asks for a second click (Yes, delete) and then removes that run folder from data/output for good; it is refused while a job is using the run or the folder was written in the last minute.
04

Reading the report

Replay timeline

The annotated video with lanes for judge events, falls and each foot's placements (green good, red poor). Click a tick to jump there.

Judge

IFSC-style Start / Zone / Top. Zone is the hold 60% up the route; Top is both hands on the last hold, controlled if held 1 s with still hips. Result: TOP, ZONE or NO SCORE.

Landing safety

Each landing is a fall, jump-off or downclimb, scored from 100: minus for stiff knees, feet off the pad, hand posting, feet out of sync, big fast drops. Drop is in body-lengths.

Silent feet

Each foot placement scored from 100 (readjusts, jitter, impact speed, precision). The mean is graded A (90+) to E (<60), with the three worst placements shown.

Dyno lab

Moves between holds classed static, deadpoint, dyno or out of reach against this climber's reach envelope, with the margin left over and a VLM second opinion on up to 4.

Reward & RL

Every moment of your climb scored by one reward function (progress, zone, top, reach, dyno risk, footwork, falls, time), shown as a curve and a per-term breakdown. A Q-learning agent then learns its own beta on a hands-only model of the same route under the same reward; compare its moves and return with yours. The model ignores feet and body height, so the agent is optimistic.

Coach note

A short text note from Qwen, written from the measured numbers. It is commentary, not an independent judge. Absent when VLM credits are off.

A caveat

Every threshold was tuned on one test clip. Use the numbers to compare your own attempts, not as absolute scores.

05

Wall scout (photos)

Before filming, photograph the empty wall to see which colours SAM 3.1 separates cleanly and how many holds each route has. One SAM call per photo per colour (~$0.001 each). Output goes to data/output/scout/<timestamp>/.

python scout.py                                   # data/input/photos/jpg
python scout.py <photos_dir> --colors blue,green,pink
iPhone .HEIC photos must be converted to JPG first; the env's ffmpeg can decode them, e.g. ffmpeg -i IMG_0001.HEIC IMG_0001.jpg.
06

Sharing it

A quick public link to the dashboard:

cloudflared tunnel --url http://localhost:8000
Anyone with that link can press RUN and spend your VLM credits. Only tunnel the dashboard while you are demoing. To share results, serve a run's report folder instead:
cd data/output/<run>
python -m http.server 8080                        # http://localhost:8080/report.html
cloudflared tunnel --url http://localhost:8080
07

Command line

The dashboard runs these two scripts for you. Without it, put clips in data/input/current/ and run:

python main.py                              # holds + pose, route read
python safety_report.py                     # newest run under data/output/
python safety_report.py <run_dir>           # a specific run or clip subfolder
python safety_report.py <run_dir> --no-vlm  # no gateway calls

Then open report.html in the run folder. Colour and grade come from CVJ_HOLD_COLOR and CVJ_ROUTE_GRADE (defaults blue, VB); CVJ_INPUT_DIR changes the input folder.

08

Troubleshooting

conda is not recognised
Conda is not on your PATH. Open Anaconda Prompt from the Start menu and run the commands there.
Colours look washed out
An iPhone HDR clip: conda-forge ffmpeg cannot tone-map it on Windows. Detection is usually fine; film in SDR to fix the look.
"No input videos found"
No clip where main.py looks. Upload one on the dashboard, or put it in data/input/current/.
Detection looks off
Open holds.png in the run folder first: it shows the detected route on a clean frame, and nearly every bad result starts there (wrong colour, missed or extra holds).
Port 8000 is busy
Start on another port: python app.py --port 8001.
